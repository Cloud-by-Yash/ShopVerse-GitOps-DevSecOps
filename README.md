# ShopVerse — Production GitOps Delivery on AWS EKS

An Infrastructure-as-Code (IaC) and GitOps platform delivering zero-downtime progressive deployments, automated image write-backs, and self-healing cluster orchestration on AWS EKS. 

*This repository governs platform state, cloud infrastructure, and delivery pipelines. Application code and CI workflows are decoupled in [Shopverse-App](#related-repositories).*

---

## Architecture & Tech Stack

| Layer | Tooling | Responsibility |
| :--- | :--- | :--- |
| **Infrastructure** | Terraform | Multi-AZ VPC, EKS Cluster, Private RDS (MySQL), IRSA Roles |
| **Cluster Add-ons** | Helm (`helm_release`) | AWS Load Balancer Controller, Metrics Server, Cluster Autoscaler |
| **Manifest Orchestration** | Kustomize | Declarative Kubernetes manifests (`Deployments`, `Services`, `Ingress`, `HPA`) |
| **GitOps & Delivery** | Argo CD + Image Updater | Automated reconciliation, registry polling, and Git write-back |

## GitOps Automated Delivery Flow

> **[ Developer Push ]** ──> **[ GitHub Actions CI ]** ──> **[ Build & Push SHA Tag to Docker Hub ]**
> &nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp; **│**
> **[ EKS Rolling Update ]** <── **[ Argo CD Sync ]** <── **[ Git Commit ]** <── **[ Argo CD Image Updater ]**

1. **CI Pipeline:** Code pushed to `Shopverse-App` triggers GitHub Actions to test, build, and publish an immutable SHA-tagged image to Docker Hub.
2. **Registry Detection:** Argo CD Image Updater detects the new image tag on Docker Hub.
3. **Declarative Write-Back:** Image Updater commits the new tag directly to `k8s/kustomization.yaml` inside this repository.
4. **GitOps Reconciliation:** Argo CD detects the Git commit and automatically triggers a zero-downtime rolling update in EKS.
5. **Traffic Routing:** AWS Load Balancer Controller maintains active traffic flow to healthy pods throughout the rollout.

## Production Security & Platform Standards

* **Zero Static AWS Credentials:** All cluster workloads leverage **IAM Roles for Service Accounts (IRSA)**. No long-lived AWS keys exist within the Kubernetes environment.
* **Isolated Data Tier:** Amazon RDS (MySQL) resides in dedicated private subnets with strict security group isolation from public traffic.
* **Secret Drift Exclusion:** Production secrets are injected directly post-bootstrap. `k8s/secret.yaml` contains placeholders only, and Argo CD is configured with `ignoreDifferences` to prevent automated syncs from overwriting live secrets.
* **Self-Healing State:** Argo CD operates with `prune: true` and `selfHeal: true`. Any manual `kubectl` interventions or cluster drift are automatically overridden to match Git.

## Engineering Decisions & Hard Problems Solved

**Kustomize Environment Flat Structure**  
Chosen over Helm for app manifests to keep configuration purely declarative. Avoided premature abstraction (`base/overlays`) since this platform runs a single production environment—reducing complexity without sacrificing modularity.

**Fixing Silent Override Precedence Bug in Image Updater**  
* **Issue:** Image Updater was committing updates, but running pods remained on old tags. 
* **Root Cause:** Image Updater defaulted to writing overrides to `.argocd-source-<app>.yaml`. An old override file was silently taking precedence over `kustomization.yaml` during Argo CD manifest rendering.
* **Fix:** Enforced `writeBackTarget: kustomization` in the `ImageUpdater` CRD to unify all state updates into a single version-controlled source of truth.

**Resolving Cluster Autoscaler `CrashLoopBackOff`**  
* **Issue:** Autoscaler pod failed AWS authentication on startup.
* **Root Cause:** Mismatch between the ServiceAccount name generated by the Helm chart and the name configured in Terraform's IRSA trust policy.
* **Fix:** Explicitly set `rbac.serviceAccount.name` in Terraform's `helm_release` definition to strictly align the IAM trust relationship with the deployed service account.

**Navigating Argo CD Image Updater v1.0.0 Breaking Changes**  
* **Issue:** Legacy annotation-based image updater configurations failed to execute.
* **Fix:** Migrated completely to the v1.0.0 custom resource schema (`ImageUpdater` CR), implementing the native `git:secret:<namespace>/<secret>` credential syntax and `newest-build` update strategies.
